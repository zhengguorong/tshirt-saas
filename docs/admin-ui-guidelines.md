# 印坊商家后台：界面与交互规范

## 适用范围与参考

适用于商家 `/admin` 的列表、详情、新建、编辑与设置页，以及它们使用的共享组件。后台服务店主与店员，任务是管理商品、接单、准备生产资料与发货。页面应像经营工具，不使用官网式大标题、装饰卡片、营销横幅或虚构统计。

组件库沿用 Ant Design。主题入口为 `apps/web/src/components/admin/antd-root.tsx`，布局为 `admin-shell.tsx`，样式为 `apps/web/src/app/admin/admin.css`。订单详情的实现参考 `order-detail-view.tsx`；参考布局，不复制其中的订单状态判断到其他业务。新页面优先复用这些约定，避免随意重设颜色、字号、阴影和圆角。

## 先确定任务，再画布局

开始实现前，明确：谁使用、当前业务状态、最重要的信息、下一步主要操作，以及加载/空白/失败/权限不足时显示什么。按用户任务分区，不按接口字段或数据库表拆卡片。

## 页面结构

### 列表

1. 标题与简短用途说明，右侧放主要创建操作。
2. 仅显示有真实数据依据的概览，明确统计范围。
3. 搜索/筛选与列表紧邻。明确是搜索全部数据还是当前已加载记录。
4. 分开“尚无记录”和“筛选无结果”；后者可清除筛选。
5. 状态使用文字与颜色共同表达；行内明确提供可通过键盘访问的详情链接。
6. 金额靠右、数字等宽。长商品名和复杂规格允许换行或提供完整信息入口。

### 详情（必须遵守）

- 页首：返回入口、页面名称、业务标识/复制、状态、关键时间；金额等主要结果单独对齐展示。
- 紧接状态说明：告诉用户当前发生了什么，以及下一步可以做什么。步骤条不得与实际业务状态矛盾。
- 桌面主区域使用 `minmax(0, 1fr)` 的主列与约 300–340px 的辅助列；内容不足时不强行拆列。
- 主列承载商品/明细、相关生产资料、关联单据与历史记录；辅助列承载当前状态可执行的操作、联系方式/地址和费用摘要。
- 收货信息与金额明细必须分区。不要把姓名、电话、地址、费用塞进同一组描述列表。
- 商品名称与规格放在同一区域，长名称不能挤压状态标签、操作和窄侧栏。
- 图片、效果图、印刷图应可预览，使用 `contain`，不裁掉生产内容。用标签区分正反面与文件类型。
- 工艺单等关联记录应是带清晰标题和去向的链接；没有资料时按业务状态解释，不默认显示“生成中”。
- 当前状态的主要操作应清晰可见；不要同时把“发货”“退款”“重新生成”都做成同等醒目的主按钮。
- 退款、删除、关闭订单等危险/低频操作放进“更多操作”或独立危险区域。确认框说明对象、后果与必要原因。不要一点击就提交。
- 不要用强制等高、绝对定位或固定页面高度来掩盖不合理的信息分组。

### 表单

- 使用带标签与校验的 Form.Item；必填原因与服务端规则保持一致。
- 按基本资料、规格/颜色、价格/印区、发布设置等真实任务分组。
- 简短相关字段可双列；地址、说明等长字段使用整行。手机上字段回到单列。
- 错误时保留输入，显示可操作的信息。成功后有反馈并更新可见状态。
- 可编辑内容与只读信息视觉分离。用校验说明问题，不依赖 placeholder 代替标签。

## 视觉基础

- 主操作蓝色沿用主题 `#3155e7`；白卡片、浅灰蓝背景、细边框。
- 文本颜色沿用主题；说明文字不可过淡。实际业务信息通常不小于 12px，辅助标签不小于 10px。
- 页面标题 22–24px，区块标题 14–16px。不要所有文本都加粗。
- 页面间距约 24–32px，区块间距 20–24px，表单字段间距 16–24px；用统一节奏，不堆叠空白。
- 8–10px 圆角，克制阴影。图标只用于识别功能，不给每个字段加装饰。
- 新的可复用布局用有意义的 CSS 类；避免长串重复的内联布局/颜色。

## 交互与状态

- 异步提交必须有 loading、阻止重复提交、失败提示与 finally 复位；失败不得清空用户输入。
- 有权限/业务状态限制的动作按现有后端规则显示；UI 隐藏不能替代服务端权限检查。
- 查询、复制、展开折叠、预览、返回等真实可用，不添加没有功能的按钮。
- 不宣称后端未实现的能力，例如真实支付渠道退款、导出、消息推送。
- 日期必须采用业务约定的时区。不要把格式变化误当成时间转换。

## 手机与可访问性

- 在约 390px 与 1440px 检查。页面本身不出现横向滚动；宽表格可在自身容器中滚动。
- 详情布局在约 850px 以下改成单列。主要任务不能只依赖桌面侧栏，必要操作必须可发现。
- 导航抽屉可关闭，选择后收起；弹窗、图片预览与表单可以用键盘操作。
- 按钮有清晰文字或可访问名称；输入有 label；颜色不作为唯一状态标识。
- 财务金额、规格、姓名和长地址在窄屏上不得被裁掉。
- 工艺单保持打印布局；后台导航、操作按钮不能混进打印输出。

## 交付前验收

按变化范围验证，不为简单样式编写重复实现的测试：

- 构建/类型检查通过，无本次引入的组件弃用或运行时错误。
- 实际查看桌面和手机页面，不只检查 JSX 或截图尺寸。
- 覆盖相关业务状态：有/无文件、生成失败、无关联单据、可操作/不可操作。
- 检查长商品名、长地址、多商品、空记录；没有对应数据时明确记录验证边界。
- 验证表单空值校验、确认框取消、链接跳转、失败时 loading 复位。不要为测试在真实订单上执行发货或退款。
- 汇报具体改动、完成的验证与未覆盖状态。不能仅以“更好看”“更现代”作为验收结论。
